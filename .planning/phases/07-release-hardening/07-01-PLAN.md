# Plan 07-01: Zero Deprecation Warnings

**Phase**: 07 — Release Hardening
**Requirements**: HARD-01 (edgartools migration), HARD-03 (Pydantic ConfigDict)
**Goal**: `uv run pytest tests/ -x -m "not live_api" -W error::DeprecationWarning` passes with zero warnings

## Overview

Fix all 5 deprecation warnings in the test suite:
- 3 edgartools warnings (from internal imports, triggered by `latest.obj()` / `latest.text()`)
- 2 Pydantic `class Config` warnings (in TinyTroupe fork's SimulationValidator)

## Tasks

### Task 1: Migrate edgartools filing extraction to HTMLParser

**File**: `src/tinyic/data/filings.py`

Rewrite `fetch_filings()` to use `edgar.documents.HTMLParser` instead of the `.obj()` / `.text()` path that triggers deprecated internal imports.

**Steps**:
1. Replace the `.obj()` call with `HTMLParser`-based extraction:
   - Get filing HTML via `latest.html()` or `latest.document.content()`
   - Parse with `HTMLParser.create_for_ai().parse(html)` to get a `Document`
   - Use the `Document` API to extract sections (Item 1, Item 1A, Item 7 for 10-K; Part I, Item 1, Item 2 for 10-Q)
   - If section extraction fails, fall back to `MarkdownRenderer` or `TextRenderer` for plain text
2. Replace the `.text()` fallback with `TextRenderer` or `document.markdown()` from the new API
3. Keep the same return shape (`FilingSummary` with truncated text)
4. Keep the same error handling pattern (log warning, return None on failure)

**Acceptance**:
- `from edgar.files.html` and `from edgar.files.htmltools` are not imported by our code path
- Filing extraction still works for 10-K and 10-Q
- Existing mocked tests pass unchanged (they mock at the `Company`/`filings` level)

### Task 2: Fix Pydantic class Config deprecation

**File**: `src/tinytroupe/validation/simulation_validator.py`

**Steps**:
1. Add `ConfigDict` to the pydantic import: `from pydantic import BaseModel, Field, ConfigDict`

   class Config:

3. In `SimulationExperimentEmpiricalValidationResult` (line 735), apply the same replacement
4. Verify no other Pydantic v1 patterns remain in the file

**Acceptance**:
- `PydanticDeprecatedSince20` warning no longer appears
- Module imports without errors

### Task 3: Suppress edgartools import-level warnings in pytest config

**File**: `pyproject.toml` → `[tool.pytest.ini_options]`

The edgartools 5.25.1 package emits deprecation warnings from its own internal import chain (`edgar._markdown` → `edgar.files.html_documents`). These fire at import time before any of our code runs. Since we've migrated our own usage to `HTMLParser`, suppress these third-party warnings in pytest.

**Steps**:
1. Add `filterwarnings` entries to `[tool.pytest.ini_options]` in `pyproject.toml`:
   ```toml
   filterwarnings = [
       "ignore::DeprecationWarning:edgar.files.*:",
       "ignore::DeprecationWarning:edgar._markdown:",
       "ignore::DeprecationWarning:edgar._filings:",
   ]
   ```
2. These are scoped to `edgar.*` modules only — any new deprecation warnings from project code will still surface

**Acceptance**:
- `uv run pytest tests/ -x -m "not live_api"` shows 0 warnings
- Non-edgar deprecation warnings still surface normally

### Task 4: Verify zero warnings

**Steps**:

2. Run `uv run pytest tests/ -x -m "not live_api" -W error::DeprecationWarning` — should pass (no DeprecationWarning raised as error)
3. Verify all 154 tests still pass

**Acceptance**:
