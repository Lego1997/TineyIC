## Key Accomplishments

1. **Zero deprecation warnings + stable test baseline** — Migrated edgartools to HTMLParser API, fixed Pydantic ConfigDict, stabilized all 7 live API tests with timeouts
2. **Anti-convergence debate controls** — Persona-specific reinforcement prompts in all phases + rotating devil's advocate role in cross-examination with clean role release
3. **Investment memo + disagreement engine** — Full narrative memo with 5 sections and section-level grounding, cross-persona disagreement extraction with evidence quotes, Markdown/DOCX export
4. **Complete UI delivery** — Company data sidebar (financials, price chart, warnings), tabbed post-debate view (Scorecard | Memo | Disagreements), download buttons, per-debate cost display
5. **Runtime model selection** — Sidebar dropdown with configurable model list, runtime config override for all LLM calls, automatic restore in finally block
6. **Deep research pipeline** — Web search via OpenAI Responses API + LLM synthesis producing structured ResearchBrief covering 5 investment analysis dimensions, toggleable via UI

## Phases

### Phase 7: Release Hardening
**Goal**: Zero deprecation warnings, zero deselected tests, and a cost stats hook ready for UI consumption
**Depends on**: Nothing (first v1.1 phase, independent gate)
**Requirements**: HARD-01, HARD-02, HARD-03, HARD-04
**Success Criteria**:
  1. `uv run pytest tests/ -x -m "not live_api"` produces 0 deprecation warnings from edgartools or Pydantic in project-owned code
  2. edgartools usage in `src/tinyic/data/filings.py` uses `edgar.documents.HTMLParser` (or equivalent non-deprecated API)
  3. All 7 previously-deselected `live_api` tests either pass when API keys are present, or are removed with a documented rationale
  4. `SimulationValidator` in TinyTroupe fork uses `model_config = ConfigDict(...)` instead of `class Config`
  5. A function `get_debate_cost_stats()` exists that returns token counts and estimated cost from `OpenAIClient`

Plans:
- [x] 07-01-PLAN.md — Zero deprecation warnings: edgartools HTMLParser migration + Pydantic ConfigDict fix + pytest warning filters
- [x] 07-02-PLAN.md — Live API test stabilization + cost stats exposure via DebateResult.cost_stats and get_debate_cost_stats()

### Phase 8: Debate Quality Controls
**Goal**: Personas maintain distinct positions throughout multi-round debates, with at least one structurally dissenting voice during cross-examination
**Depends on**: Phase 7 (clean test baseline required)
**Requirements**: DEBT-04, DEBT-05, PERS-08
**Success Criteria**:
  1. Anti-convergence controls are active during debate via persona-specific reinforcement prompts
  2. During cross-examination, one persona is assigned a rotating devil's advocate role
  3. The devil's advocate assignment rotates and does not constrain final votes
  4. An automated differentiation regression test asserts persona analyses remain distinct (TF-IDF cosine similarity < 0.70)
  5. The convergence detection test runs without API keys using recorded fixtures

Plans:
- [x] 08-01-PLAN.md — Anti-convergence reinforcement prompts + rotating devil's advocate role injection in orchestrator._step()
- [x] 08-02-PLAN.md — Differentiation regression tests with TF-IDF cosine similarity on recorded debate fixtures

### Phase 9: Memo & Disagreement Engine
**Goal**: The system produces a publishable investment memo and a structured disagreement analysis from every completed debate
**Depends on**: Phase 7 (hardening), Phase 8 (debate quality)
**Requirements**: OUTP-03, OUTP-04, OUTP-05
**Success Criteria**:
  1. InvestmentMemo with structured sections: Executive Summary, Investment Thesis, Key Risks, Valuation Discussion, Final Verdict
  2. Section-level grounding referencing contributing personas and supporting data
  3. DisagreementAnalysis identifying top 3 divergence dimensions with evidence quotes
  4. Markdown + DOCX export with graceful pandoc fallback
  5. Unit tests verify memo structure, disagreement extraction, and export without API calls

Plans:
- [x] 09-01-PLAN.md — InvestmentMemo + DisagreementAnalysis models, MemoGenerator with LLM synthesis, and unit tests
- [x] 09-02-PLAN.md — ExportManager for Markdown/DOCX output with graceful pandoc fallback and export tests

### Phase 10: UI Delivery
**Goal**: Users see company data alongside the debate, can download all outputs, and see what the debate cost
**Depends on**: Phase 7 (cost stats hook), Phase 9 (memo and export artifacts)
**Requirements**: UI-05, UI-07, OPS-01
**Success Criteria**:
  1. Data sidebar shows key financials, price chart, freshness timestamp, and data source warnings
  2. Download buttons for investment memo (MD/DOCX), scorecard (MD), and transcript (MD)
  3. Per-debate token usage and estimated cost displayed after debate completes
  4. Data sidebar updates immediately after data fetching (before debate rounds)
  5. All new UI components work with existing debate flow

Plans:
- [x] 10-01-PLAN.md — Company data sidebar (financials, price chart, warnings) and per-debate cost display
- [x] 10-02-PLAN.md — Memo/disagreement views, download buttons, post-debate tabs

### Phase 11: Model Selection
**Goal**: Users can choose which LLM model powers the debate via a sidebar dropdown
**Depends on**: Phase 7 (clean baseline)
**Requirements**: CONFIG-01, CONFIG-02, CONFIG-03
**Success Criteria**:
  1. Sidebar model dropdown populated from configurable MODEL_OPTIONS list
  2. Selected model overrides config.ini at runtime for all LLM calls in that debate session
  3. Each model option displays a brief description of its strengths
  4. Default selection matches current config.ini MODEL value
  5. Model selection locked during active debate

Plans:
- [x] 11-01-PLAN.md — Model dropdown in sidebar with runtime config override and tests

### Phase 12: Deep Research Pipeline
**Goal**: Every debate is informed by a comprehensive, LLM-synthesized research brief covering business, competition, industry, management, and analyst perspectives
**Depends on**: Phase 7 (clean baseline), Phase 11 (model selection — research uses the selected model)
**Requirements**: DATA-06, DATA-07, DATA-08, DATA-09
**Success Criteria**:
  1. build_data_package() includes optional deep research step using web search + LLM synthesis
  2. ResearchBrief covers 5 areas: business model, industry trends, management, recent catalysts, analyst perspectives
  3. ResearchBrief stored on DataPackage and included in to_context_string()
  4. Research step toggleable via UI checkbox (default: enabled)
  5. Graceful degradation when web search or synthesis fails
  6. Unit tests verify model, pipeline integration, toggle behavior, and failure handling

Plans:
- [x] 12-01-PLAN.md — ResearchBrief model, web search + LLM synthesis pipeline, pipeline integration with deep_research toggle
- [x] 12-02-PLAN.md — UI checkbox for deep research toggle, research brief display in data sidebar
